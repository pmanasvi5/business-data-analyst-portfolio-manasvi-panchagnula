# AI Knowledge Assistant

A small Python and Streamlit portfolio project that answers questions about uploaded PDFs using retrieval-augmented generation (RAG) and the Claude API. All application logic is in `app.py`.

## Business problem

Employees and analysts spend time searching policy documents, handbooks, and reports. This assistant retrieves useful passages and drafts a concise answer with references that a person can check against the original documents.

## Features

- Upload one or multiple text-based PDFs.
- Extract text page by page and split into 800-character chunks with 100-character overlap, preserving filename and page number.
- Normalize questions and retrieve up to three matching chunks using TF-IDF and cosine similarity.
- Ask Claude for a concise, context-grounded answer with inline file/page citations.
- Display unique retrieved source references and an expandable Retrieved Context section.
- Record Looks Correct / Needs Review feedback in Streamlit session state.
- Handle missing files, empty/scanned/broken PDFs, missing keys, no matching text, and common API errors.

## Simple architecture

Upload PDF -> Extract Text -> Chunk -> TF-IDF Retrieval -> Claude -> Answer + Citations

No vector database, framework for RAG, authentication, or persistent database is used.

## Installation and running

Requires Python 3.10+ and an Anthropic API key with API credits and model access.
Run these commands from this project's folder:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

On Windows PowerShell use `python -m venv .venv`, `.venv\Scripts\Activate.ps1`, and `Copy-Item .env.example .env` instead.

Edit `.env` and replace the placeholder:

```dotenv
ANTHROPIC_API_KEY=your_real_key
ANTHROPIC_MODEL=claude-haiku-4-5
```

Then launch:

```bash
python -m streamlit run app.py
```

Open the localhost URL shown in the terminal. Upload a text PDF, ask a question using words found in it, review the retrieved context and original pages, then click a feedback button. Restart the app after changing `.env`. Existing environment variables take priority over `.env`; do not commit your key. The app loads `.env` from beside `app.py`. You can change `ANTHROPIC_MODEL` to a model available to your account.

## How RAG works here

1. PyPDF extracts each page separately; page numbers are physical PDF positions starting at 1 (printed page labels may differ).
2. The app creates small overlapping chunks with filename and page metadata. Chunks never cross pages.
3. TF-IDF converts text into sparse numerical features representing weighted word frequencies. Cosine similarity ranks chunks against the question. This is lexical retrieval, not neural embeddings.
4. Simple prompt refinement normalizes Unicode, whitespace, and case for retrieval. It does not rewrite intent or require another API call. English stop words are removed by the vectorizer.
5. Up to three positive-score chunks and the original question are sent to Claude via `client.messages.create`, together with grounding instructions. Whole PDFs and previous answers are not sent.

The index is built when uploads change and kept in the current session. No match means no Claude request: the app displays the standard insufficient-information answer with no sources, and the reviewer can still leave feedback. A positive word-overlap score does not prove that the context answers the question; Claude is instructed to decline when evidence is insufficient.

## How hallucinations are reduced

The system prompt restricts the answer to the supplied context, prohibits invented facts, requests concise answers and file/page citations, and requires this response when evidence is missing: “I don't have enough information in the uploaded documents.” It also tells Claude to treat document instructions as untrusted text. If a response starts with the required insufficient-information sentence, the app keeps only that sentence so the refusal format stays consistent.

These measures reduce risk but do not guarantee accuracy or defeat every prompt injection. Inline citations are generated by Claude and are not automatically verified. The Sources list is generated directly from retrieved metadata and lists retrieved pages, not a guarantee that every page supports every claim. Humans should verify the answer against Retrieved Context and the original PDF.

## Human validation

After checking the evidence, the reviewer selects **Looks Correct** or **Needs Review**. Each click appends the question, answer, retrieved sources, and label to `st.session_state.feedback`; the latest label appears below the answer. Feedback survives ordinary Streamlit reruns in the same session, but is not permanently saved and may be lost when the session ends or the page reloads. Feedback does not train Claude or automatically change future answers.

## Technologies

Python 3.10+, Streamlit (interface/session state), Anthropic Python SDK (Claude Messages API), PyPDF (extraction), scikit-learn (TF-IDF/cosine similarity), and python-dotenv (local configuration).

API integration follows [Anthropic's Python SDK documentation](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/python) and [Messages API reference](https://platform.claude.com/docs/en/api/python/messages/create).

## Scope and limitations

This is intended for a few small English text PDFs. Scanned images require OCR, which is not included; complex tables and layouts may extract poorly. TF-IDF can miss synonyms and questions requiring evidence spread across more than three chunks. Character splitting may divide sentences. Use distinct filenames so source references are easy to distinguish. Uploaded content stays in session memory locally; retrieved excerpts and questions leave the app for Anthropic when submitted. API requests can incur charges.

## Three interview questions and answers

**1. What makes this a RAG application?**

It retrieves document passages before generating an answer. I use TF-IDF and cosine similarity to select up to three relevant chunks, then provide those chunks as context to Claude. The model is not fine-tuned on the documents.

**2. Why did you use TF-IDF instead of a vector database?**

For a small portfolio demo, TF-IDF is simple, inexpensive, and easy to explain. It ranks passages using weighted word overlap without another service. The tradeoff is weaker matching for synonyms and paraphrases, and it is not designed here for large document collections.

**3. How do you validate AI responses?**

I preserve file/page metadata, display the retrieved excerpts, and ask Claude to cite its answer. A reviewer compares the answer with that evidence and marks Looks Correct or Needs Review. The labels are stored in session state for the demo; they are human judgments, not an accuracy metric or a guarantee of correctness.
